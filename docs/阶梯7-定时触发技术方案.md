# 阶梯 7 · 定时触发（Quartz）技术方案

> 统筹（Claude）2026-09-30 定稿。目标：工作流支持 cron 定时自动执行。
> 简历收益：Quartz 定时调度、动态任务注册、调度幂等设计。
> 面试收益：Quartz 内存模式 vs JDBC 持久化、misfire 策略、定时与手动的并发冲突（分布式锁兜底）。

## 1. 架构

```
用户配置：工作流 → 定时计划（cron + 启用开关 + 输入参数 JSON）
后端：Quartz 内存模式，启动时加载所有启用的计划动态注册 Trigger
触发时：UserContext 注入归属用户 → 复用 submit 链路（锁 → queued → MQ → 执行）
      ——定时执行与手动执行走同一条管道，分布式锁天然挡住"定时+手动撞车"（后者 409）
执行记录：executions 新增 trigger_type（manual/scheduled），历史页可见来源
```

**关键设计**：定时触发**完全复用 submit**，不新开执行路径——队列、重试、死信、SSE 全部免费继承。

## 2. 数据模型（新增 1 表 + executions 加 1 列）

```sql
CREATE TABLE workflow_schedules (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    workflow_id BIGINT NOT NULL,
    cron VARCHAR(64) NOT NULL,          -- 标准 6 段 cron
    enabled TINYINT DEFAULT 1,
    input TEXT,                          -- 执行入参 JSON（空 = 用字段默认值）
    last_run_at DATETIME NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_workflow (workflow_id)
);
ALTER TABLE executions ADD COLUMN trigger_type VARCHAR(10) NOT NULL DEFAULT 'manual';
```

## 3. 契约 v1.7 变更

| 接口 | 说明 |
|------|------|
| GET /api/workflows/{id}/schedule | 读计划（无计划返回 null 或 404？——返回 `{ "configured": false }` 更简单，GLM 定并上报） |
| PUT /api/workflows/{id}/schedule | {cron, enabled, input} 写入/更新（cron 非法 → 400 SCHEDULE_INVALID） |
| DELETE /api/workflows/{id}/schedule | 204 删除计划 |
| executions 字段 | 新增 triggerType（manual/scheduled），历史列表与详情都带 |

- 新错误码：`SCHEDULE_INVALID(400, "cron 表达式非法")`
- 定时执行缺必填字段：照常 400 INVALID_INPUT 语义（input 里带上即可），执行失败走正常失败链路

## 4. Quartz 决策（面试答案预埋）

- **用 spring-boot-starter-quartz + 内存模式（RAMJobStore）**：动态注册/删除 Trigger 简单；我们的执行本身已由 MQ 持久化（任务不丢），Quartz 只负责"到点触发"这一下——触发即入 MQ，所以内存模式够用，**重启丢失的只是"未触发的未来计划"由启动加载恢复**（从 DB 读计划重建）
- **JDBC 持久化什么时候才需要**：集群多实例部署时（防重复触发）；单实例内存模式即可——这是标准答案
- **misfire 策略**：MISFIRE_INSTRUCTION_FIRE_NOW（错过就立即补一次）或 DO_NOTHING——执行幂等有 MQ+锁兜底，GLM 定并上报
- 调度线程里手动 UserContext.set(userId, role)（try/finally clear），复用归属校验

## 5. 分工与禁区

- **GLM（backend）**：quartz 依赖、ScheduleService（CRUD+动态注册/注销+启动恢复加载）、ScheduleJob（触发→UserContext→submit）、executions.trigger_type（实体/DDL/VO/历史接口）、契约 v1.7 端点；**禁区照旧**（engine、已冻结文件；submit 链路只加 trigger_type 参数，不改逻辑）
- **WorkBuddy（frontend）**：工作流编辑器加"定时计划"面板（cron 输入框+常用示例下拉（每小时/每天/每周）+启用开关+入参编辑）、执行历史列表/详情显示"定时/手动"来源标记；cron 合法性前端预校验（简单正则即可，后端为准）

## 6. 验收标准

- [ ] PUT cron 计划 → 到点自动执行（真实 LLM）→ executions 里 triggerType=scheduled

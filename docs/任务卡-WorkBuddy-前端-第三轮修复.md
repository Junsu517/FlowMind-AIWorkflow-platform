## 任务清单（按用户反馈原话归纳）

### 1. 费用极小值别再科学计数法（用户：$7.60e-5 还是浮点数）

- `utils/format.js` 的 `formatCost`：现在 `n < 0.0001` 时用 `toExponential(2)` 显示 `$7.60e-5`
- 改为：`0 < n < 0.0001` → 显示 **`<$0.0001`**（"小于"语义，非计科读者也懂）
- 自查：执行一个短 LLM 调用让费用落在 1e-5 量级，三处（调试/列表/详情）显示一致

### 2. 连线选中后删不掉（用户：多连了一条线，不想删节点，线就删不掉了）

- 根因：`WorkflowEdit.vue` 第 55 行 `:delete-key-code="null"` 禁用了键盘删除，且无其他删除入口
- 修复（两条都做）：
  1. `:delete-key-code="['Delete', 'Backspace']"`（数组形式同时支持两个键）
  2. 选中连线/节点时，画布工具栏出现"删除所选"按钮（或等效的可见入口），不要只依赖键盘
- 自查：拖一条多余连线 → 点选 → Delete 或按钮 → 线消失且不影响节点；表单版（?mode=form）不涉及此问题

### 3. 条件分支规则区 UI 两处问题（用户：等于和 branch a 各有重复括号；handle 词汇要有中文）

- `NodeConfigForm.vue` 条件规则区（约 165-200 行）：
  1. **重复括号 bug**：操作符（等于）和分支名（branch_a）附近各有一处渲染出多余/重复的括号块——定位是模板里拼接的括号字符与组件自带文案重复，清理掉
  2. **handle 中文化**：`r.handle` 输入框 placeholder 从 `handle` 改为 `分支标识（如 beijing）`；区块提示语（171 行附近）改为 `按顺序匹配，命中则走对应分支（handle）`——保留英文术语但带中文解释
- 自查：截图修复前后对比；表单版同步检查（共用组件的话应该自动一致）

### 4. 节点灰色状态点误导（用户：以为有用，实际只是装饰）

- 现状：每个节点卡片有灰色状态点，idle 时也是灰色，用户误以为可交互
- 修复：**idle（status=pending）时不渲染状态点**，只有执行中（running/success/skipped/failed）才显示（NodeFrame.vue 的 status 渲染逻辑）
- 自查：进入编辑器不执行 → 无灰点；执行后状态点正常流转

### 5. 近距离连线"先超出再回去"（用户：瑕疵）

- 现状：两节点距离近时，贝塞尔曲线控制点外扩导致线越过目标节点再折回
- 修复方案（任选，效果优先）：默认边类型改 **smoothstep**（小圆角折线）或调低贝塞尔曲率；在 VueFlow 组件的 `defaultEdgeOptions` 或全局 CSS 处理
- 自查：两节点间隔 ~40px 连接，线不再突入节点内部

### 6. （可选加固，时间允许再做）登录后用户信息以服务端为准

- 背景：用户发现 F12 改 localStorage 的 user.role 能骗过前端显示。后端是安全的（鉴权只看 JWT），但前端可以做自我修复：
- 做法：应用启动时若存在 token，静默调 `GET /auth/me` 刷新本地 user 缓存（失败才沿用缓存）。这个可选，不做也行（统筹已向用户解释清楚安全边界）

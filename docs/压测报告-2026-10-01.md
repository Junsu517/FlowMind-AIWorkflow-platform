# FlowMind 压测报告（JMeter 5.6.3，2026-10-01）

> 环境：生产服务器 2C2G（FlowMind mqueue 模式 + MySQL + Redis + RabbitMQ + Chroma），JMeter 本机发起，公网链路。
> 测试计划：docs/../jmeter-work/flowmind-load.jmx（三线程组：限流验证 / 并发执行 / 静态资源）。

## 1. 执行接口并发提交（10 并发 × 10 独立用户）

| 指标 | 数值 |
|------|------|
| 请求数 | 10（全部 202 成功，0 失败） |
| 平均延迟 | **222 ms** |
| p95 / p99 | **240 ms / 240 ms** |
| 最大 | 242 ms |

提交路径 = Redis 分布式锁 + 落 queued 行 + MQ publish confirm，10 并发下延迟平坦——平台侧开销稳定在 ~220ms 量级（真实 LLM 执行在 MQ 消费者异步进行，不影响提交响应）。

## 2. 限流验证（同一用户 12 连发，间隔 <1s）

| 结果 | 数量 |
|------|------|
| 202 放行 | 9 |
| 429 RATE_LIMITED | 3 |

Redis Lua 原子限流在突发流量下稳定生效（10 次/分钟/用户，窗口内前序请求计入计数），无穿透。

## 3. 静态资源（20 并发 × 3 轮，无浏览器缓存）

| 资源 | 平均 | p95 | 说明 |
|------|------|-----|------|
| 首页 /fm/ | 226 ms | 279 ms | index.html（no-cache 每次校验） |
| 主 JS（gzip 437KB） | 1212 ms | 1869 ms | 带宽受限；浏览器侧 immutable 缓存 30 天后二次访问 0 网络流量 |

对比修复前：主 JS 原始 1.14MB 无压缩无缓存 → gzip 后 -62%。

## 4. 压测中的额外发现（意外收获）

- **同工作流并发请求被分布式锁精确拦截**（首轮计划 3 循环时观察到 20×409）：锁 + DB 双防线无竞态
- **归属校验有效**（压测计划 bug 导致跨用户执行时观察到 27×403 FORBIDDEN）：越权请求全部被拒

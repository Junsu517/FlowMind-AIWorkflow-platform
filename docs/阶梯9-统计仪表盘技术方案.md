> 统筹（Claude）2026-10-02 定稿。目标：平台使用统计可视化——指标卡 + 趋势折线 + 来源分布。
> 简历收益：ECharts 数据可视化、SQL 聚合统计、仪表盘设计。
> 面试收益：统计口径设计（成功率怎么算）、按天聚合 SQL（DATE_FORMAT + GROUP BY）、图表选型。

## 1. 功能与架构

```
GET /api/stats/dashboard（JWT）→ 一次返回全部聚合数据（避免多接口多次查询）：

指标卡（今日+累计）：
  总执行数 / 成功率 / 总 tokens / 总费用
  活跃工作流数 / 知识库文档数 / 已发布 API 数 / 启用定时计划数

趋势：近 30 天每日执行数 + tokens（折线图）
分布：triggerType 来源占比 manual/scheduled/api（饼图）
Top：执行次数最多的 5 个工作流（列表）

前端 /dashboard 页：4+ 指标卡 + ECharts 折线 + 饼图 + Top 列表，导航栏加"仪表盘"
```

后端一个 SQL 聚合 service（GROUP BY DATE_FORMAT(started_at, '%Y-%m-%d')），前端一次渲染。

## 3. 统计口径（面试预埋）

- **成功率** = success / (success + failed)，进行中（queued/running）不计入分母
- **近 30 天**：含今天，无数据的日期补 0（前端或后端补零都可，后端补齐更省前端逻辑）
- **totalCost** 用库里 decimal 求和，前端 formatCost 复用
- 大表聚合：executions 表加 (user_id, started_at) 组合索引——面试讲"为什么按天聚合要加索引"

## 4. 分工与禁区

- **GLM（backend）**：StatsController/Service 扩展 dashboard 聚合（一次查询或分查询组装，你定；DATE_FORMAT 按天聚合 + 来源分布 GROUP BY trigger_type + Top 工作流 JOIN workflows 取名字）、组合索引 DDL、JUnit（口径正确性：成功率计算、空数据补零、来源分布）
- **WorkBuddy（frontend）**：/dashboard 路由+导航入口、指标卡（复用 formatCost/formatNumber）、**ECharts 依赖引入**（echarts，PetCare 用过同款）、折线图（30 天执行数/tokens 双轴或切换）、饼图（来源分布）、Top 工作流列表；深色主题适配（ECharts 颜色 token 对齐视觉规范）；空数据状态（没有执行时给引导文案）
- **统筹（Claude）**：契约 v1.9、验收上线（服务器 DDL 加索引）

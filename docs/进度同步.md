### 2026-09-23（Day 3 · 事故记录：生产构建漏 VITE_USE_MOCK=false → 线上 mock 模式，已修复）
- **事故**：19:30 统一上线的前端构建只传了 VITE_API_BASE，漏了 VITE_USE_MOCK=false。而 api/index.js 的 USE_MOCK 默认 true（`?? 'true'`），导致**线上整包跑 mock 模式**：登录走浏览器本地假数据（提示"用户名或密码错误"）、请求根本不到服务器（nginx 日志零记录）
- **发现**：用户实测登录失败 → 统筹查 nginx access log 零请求 → 读代码定位 `USE_MOCK` 默认值陷阱 → 用「坏包 Qs=!0 vs 新包 Qs=!1」字节级对比坐实
- **修复**：重新构建 `MSYS_NO_PATHCONV=1 VITE_API_BASE=/fm/api VITE_USE_MOCK=false npm run build -- --base=/fm/`，已替换上线（index-CicguPdl.js），线上 chunk 验证 Qs=!1
- **防复发铁律（写入部署备忘）**：生产构建命令必须同时带 VITE_API_BASE 和 VITE_USE_MOCK=false 两个环境变量；部署后 curl 线上 chunk 验 Qs=!1 + fm/api 存在
- 插曲：部署过程中服务器短暂无响应（ping 通但 HTTP/SSH 卡死约 60s），自愈，疑似瞬时网络/负载抖动，未定位到具体原因（待观察）

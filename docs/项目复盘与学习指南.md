## 一、项目全景（30 秒版）

FlowMind 是可视化 AI 工作流平台（迷你 Dify）：用户拖拽画布把 输入/LLM/条件/HTTP 节点编排成工作流，平台负责执行编排、流式输出、知识库问答。
在线演示 http://43.108.111.175/fm/ · Gitee: junsu517/flowmind-ai-work-platform

**六个阶梯**（每个都是一次能力跃迁，简历按此展开）：

| 阶梯 | 内容 | 简历关键词 |
|------|------|-----------|
| 1 MVP | CRUD + 表单编辑器 + 顺序引擎 + SSE + 部署 | 全栈基础 |
| 2 画布 | Vue Flow 拖拽编排 | 可视化编排 |
| 3 并行调度 | 就绪队列 + 线程池 + 惰性跳过 | 执行引擎 |
| 4 Function Calling | Agent 多轮工具循环 | Agent 开发 |
| 5 RAG | 切分→向量化→Chroma→引用生成 | 检索增强生成 |
| 6 RabbitMQ | 异步解耦 + 死信 + 分布式锁 | 消息队列 |

## 二、架构演进故事线（"为什么会有这个设计"）

1. **顺序引擎 → 并行引擎（阶梯 3）**：无依赖的分支节点串行执行浪费 LLM 等待时间。改成"入边计数归零且存在活跃入边才进就绪队列"的动态调度，CompletionService 收集完成事件。**难点在汇聚节点**：多父节点只要有一条活跃路径可达就必须执行，所以"跳过判定"要推迟到入度归零时做（惰性判定）——这就是简历里"汇聚节点惰性跳过"的由来。
2. **单轮 LLM → Agent 循环（阶梯 4）**：让模型自己决定调工具。流式解析 tool_calls 分片（按 index 拼 arguments）→ 执行 → role=tool 回填 → 再问。**为什么中间轮不推给前端**：工具调用轮没有最终内容，只有最后一轮的 content 缓冲重放，保打字机体验。
3. **内存线程池 → RabbitMQ（阶梯 6）**：execution 107 事故（JVM 重启丢任务）暴露线程池的致命伤——任务在内存里，进程死任务就死。升级为消息队列：任务先落 MQ（持久化），消费者再执行，**实测击杀进程后排队任务断点续跑**。
4. **为什么单体不微服务**：这个体量（单用户数万级）单体是正确架构，Spring Cloud 是面试知识不是项目需求。面试讲"何时才需要微服务"比硬拆更出彩。

## 三、真实 bug 故事库（面试"难点"题弹药，按排查手法分类）

每个故事都能按 **现象 → 排查手段 → 根因 → 修复** 讲 2 分钟。加粗的是推荐首选。

### 用"日志"破案
1. **SSE 不可用之谜（三根因）**：线上流式全挂但轮询正常 → nginx 日志发现 SSE 请求打到了别的服务 → 根因①前端 sse.js 硬编码路径没读环境变量。继续深挖又发现根因②鉴权失败返回空 500（异常处理器自己崩了）、根因③前端不区分 401。
2. **执行卡死之谜（107）**：工作流永久 409 → **jstack 线程转储**发现执行线程池空闲、任务根本不在 JVM 里 → 定位是重启窗口丢任务 → 先做启动恢复（止血）→ 最终 MQ 根治。
3. **恢复服务与消费者启动竞态**（真 MQ 联调才发现）：消费者已把重投消息置 running，启动恢复却把它当孤儿翻 failed → 用"JVM 启动时间戳"做时间窗过滤，只翻上一进程的遗留行。

### 用"抓包/字节对比"破案
4. **线上整包 mock 模式事故**：登录全假、服务器零请求 → 读代码发现 USE_MOCK 默认 true → 用**坏包 Qs=!0 vs 新包 Qs=!1 字节级对比**坐实构建漏传 VITE_USE_MOCK=false。从此立下"生产构建双变量铁律"。
5. **Chroma 检索分数异常**：默认度量是 l2 不是 cosine → 显式指定 cosine，score=1/(1+distance)。

### 用"看渲染而不是看代码"破案
6. **条件规则"重复括号"**：DOM 文本看着正常，截图才发现是 340px 面板里 4 个输入框的圆角边框叠压 → 改成两行卡片布局 + 写重叠检测器全量扫描。
7. **Vue Flow 连线连不上**：Loose 模式只放宽 handle 类型、不能甩到节点任意位置 → 用 ::after 伪元素在连线期间撑满目标 handle 热区（伪元素不影响落点锚点）。

### 用"环境复现"破案
8. **nginx listen 80 http2 拒连一切**：nginx -t 通过、reload 成功，但本机 curl 全 000 → 回退 http2 指令即恢复。
9. **打包 jar 被锁**：mvn repackage 失败 → 8080 上有实例正跑着这个 jar 文件（Windows 文件锁）→ 打包前先查端口。

### 小坑速记（各一句话）
- Git Bash 把 `/fm/` 路径转换成 `C:/Program Files/Git/fm/` → MSYS_NO_PATHCONV=1
- Windows 控制台 GBK 会把中文 curl JSON 转坏 → 用 --data-binary @文件
- PetCare 的 uvicorn 默认占 8000 → Chroma 挪到 8001
- bcrypt 5.x 与 passlib 1.7.4 不兼容（PetCare 时代）→ 锁 bcrypt==4.0.1
- wttr.in 外部天气 API 偶发超时 → 测试 flaky 时先怀疑外部依赖

## 四、技术决策清单（面试"为什么"题库）

| 决策 | 为什么 |
|------|--------|
| 不用 LangChain4j | community 模块长期 alpha、版本矩阵复杂；OkHttp 有测试基建可锁契约。评估后自研，原理理解更深 |
| 不用 Milvus | 4G 内存起步装不下；小规模 Chroma 嵌入模式足够，讲"何时上向量库"反而加分 |
| FAISS 只了解 | C++ 库非服务，Java 绑定差 |
| SSE 不用 WebSocket | 单向流无需双向；EventSource 不能带 Authorization 头，故自研 fetch+ReadableStream |
| 不用 Spring Cloud | 单体够用；微服务是面试知识不是需求 |
| Redis Lua 原子限流 | 计数+过期两步必须原子，Lua 在 Redis 内单线程执行天然满足 |
| 重试用接力 republish 不用 requeue | requeue 改不了消息头会死循环；republish 带 x-retry-count 计数 |
| 双模式开关（thread/mqueue） | 部署安全网，一个环境变量回退；也是架构灵活性的面试素材 |
| 生产构建双变量铁律 | VITE_API_BASE + VITE_USE_MOCK=false 缺一不可（事故教训） |

## 五、代码地图（讲项目前先按这个走一遍）

```
backend/src/main/java/com/flowmind/
  engine/          ← 执行引擎（你写的）：ExecutionEngine（并行调度核心）、TopologicalSorter、
                     TemplateRenderer（{{}}引用）、ConditionEvaluator、ExecutionContext
  service/
    ExecutionService   ← 入口：submit（锁→queued→MQ/线程池分发）
    ExecutionRunner    ← 执行核心（幂等→running→引擎→落库→释放锁）
    ExecutionQueueService ← MQ 消费/重试/死信
    DistributedLockService ← Redis 锁（Lua check-and-del）
    SseEmitterRegistry ← SSE 注册中心（无消费者静默丢弃）
    LlmNodeExecutor   ← LLM 单轮 + FC 代理循环 + RAG 分支
    rag/              ← TextSplitter/EmbeddingService/ChromaStoreService/RagService
frontend/src/
  views/WorkflowEdit.vue ← 画布编辑器（Loose 连线/删除所选/smoothstep）
  utils/graphModel.js    ← 契约转换（画布⇄API，单点真理）
  utils/sse.js           ← 自研 SSE 客户端（401 统一处理）
  api/mock/              ← mock 体系（仅 dev）
docs/API契约.md          ← 接口唯一真相（每次裁决都有记录）
docs/contract_check.py   ← 机器验收（40+ 项检查）
```

**建议练习**：对着代码地图，从"用户点执行"开始，把一次执行的完整链路（前端 SSE → controller → submit → 锁 → MQ → 消费 → 引擎并行调度 → 事件回推）默写一遍。
